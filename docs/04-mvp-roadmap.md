# Примерное ТЗ последующих этапов — MVP 0.1

Документ фиксирует уже обсуждённое направление. Детальная спецификация каждого этапа создаётся непосредственно перед его разработкой.

---

# Этап 2 — Группы, дети, родители

## Backend

### Group
Поля:
- id
- organization_id
- name
- status
- created_at
- updated_at

### Child
Минимально:
- id
- organization_id
- group_id
- first_name
- last_name
- middle_name optional
- birth_date
- status
- created_at
- updated_at

Не собирать на этом этапе:
- диагнозы;
- медицинские документы;
- СНИЛС;
- паспорт;
- биометрию;
- фотографии.

### Guardian
- id
- organization_id
- user_id optional
- first_name
- last_name
- middle_name optional
- phone optional
- email optional
- status

Email и телефон не обязательны.

### ChildGuardian
Связь many-to-many:
- child_id
- guardian_id
- relation_type
- status
- created_by
- created_at

Один родитель может иметь нескольких детей.

### PARENT account
Администратор/директор может:
- создать аккаунт родителя;
- получить сгенерированный username;
- получить временный пароль один раз;
- сбросить пароль позже.

Полноценный интерфейс PARENT пока не обязателен.

## Frontend

Разделы:
- `/groups`
- `/groups/{id}`
- `/children`
- `/children/new`
- `/children/{id}`
- `/guardians`
- `/guardians/{id}`

Ключевой сценарий этапа:

```text
DIRECTOR
→ создаёт группу
→ создаёт ребёнка
→ добавляет/выбирает родителя
→ при необходимости создаёт PARENT account
→ ребёнок виден в группе
```

# Этап 3 — Сотрудники и посещаемость

## Employees

Сотрудник связан с User.

Директор:
- создаёт сотрудника;
- назначает допустимую роль;
- блокирует;
- сбрасывает пароль.

ADMIN не может назначить DIRECTOR.

## Attendance

Минимальная модель:
- child_id
- date
- status
- arrival_time optional
- departure_time optional
- comment optional
- created_by
- updated_by

Статусы:
- present
- absent
- unknown

Ввод пока ручной.

СКУД/планшет на этом этапе отсутствует.

Frontend:
- `/employees`
- `/attendance`

Фильтры посещаемости:
- дата;
- группа;
- статус;
- ребёнок.

# Этап 4 — Объявления, Dashboard, Audit

## Announcement
Получатель:
- весь сад;
- группа.

Пока без push/email/SMS.

## Dashboard
Показывает:
- активные дети;
- присутствуют;
- отсутствуют;
- без отметки;
- группы;
- сотрудники;
- краткую статистику по группам.

## Audit Log

Обязательно логировать критичные изменения:
- ребёнок создан/изменён/архивирован;
- guardian создан/изменён;
- связь ребёнок-родитель изменена;
- группа изменена;
- роль сотрудника изменена;
- пользователь заблокирован;
- пароль сброшен;
- посещаемость исправлена.

Audit Log не хранит пароль и password hash.

# После MVP

## TEACHER
Права только на свои группы и минимально необходимые данные.

Потенциально:
- список своей группы;
- посещаемость;
- объявления;
- расписание позже.

## PARENT UI
Потенциально:
- свои дети;
- посещаемость;
- объявления;
- расписание;
- доверенные лица позже.

## Планшет на входе
Отдельный проект после стабилизации основного SaaS.

Предварительная идея:
- планшет/терминал на входе;
- не смешивать реализацию с первым MVP;
- отдельная модель отказоустойчивости и доступа.

## Позже
- платежи;
- фото;
- дополнительные занятия;
- расширенная аналитика;
- сети садов;
- AI.

Каждый новый модуль проходит отдельную проверку по персональным данным и реальной бизнес-ценности.
