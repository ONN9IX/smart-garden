# Приёмка Stage 2

**Основание:** `docs/12-stage-2-data-model-and-decisions.md`, `docs/13-stage-2-backend.md`, `docs/14-stage-2-frontend.md`, `docs/15-api-contract-stage-2.md`.

## Сквозной результат

Frontend использует только `/api/v1` FastAPI и PostgreSQL. Управляющие роли DIRECTOR/ADMIN создают и архивируют группы, детей, представителей и связи. PARENT входит по временным данным, обязательно меняет пароль и попадает в технический `/parent`. Сервер отклоняет его запросы к управлению независимо от маршрутизации Frontend.

Автоматический сценарий `frontend/tests/stage2.spec.ts` в CI проходит через Browser → Next.js → FastAPI → PostgreSQL с отдельным синтетическим директором. Проверены:

1. Вход директора, смена временного пароля, создание Group, Child, Guardian и связи.
2. Создание PARENT аккаунта; временный пароль исчезает после закрытия карточки и обновления страницы.
3. Вход PARENT, принудительная смена пароля, `/parent`, отказ на прямом URL и API `/children`, выход и повторный вход.
4. Сброс пароля: прежний сеанс и прежний пароль недействительны.
5. `GROUP_NOT_EMPTY`, запрет архивации представителя со связью с активным ребёнком, затем архивация ребёнка, группы и представителя с блокировкой PARENT.
6. Планшетная и мобильная ширина, отсутствие необработанных ошибок страницы. Существующие Stage 1 browser tests остаются в том же запуске.

Backend `pytest` на PostgreSQL проверяет миграции, изоляцию двух организаций, RBAC, контракт ответов и ошибок, историю связей, сессии и идемпотентность синтетического seed. CI также выполняет Ruff, Frontend lint/build, Alembic downgrade/upgrade и полный Docker preview. Обязательные проверки Backend checks и Frontend checks должны быть зелёными перед merge.

## Персональные данные и границы Stage 2

- В dev/test/preview используются только синтетические записи; реальные данные детей и представителей туда не вводить.
- Карточка ребёнка содержит минимальные ФИО, дату рождения и группу. Контакты представителя необязательны. Медицинские сведения, документы и фотографии не собираются на Stage 2.
- Tenant берётся из серверной сессии; чужие записи скрыты ответом `404 NOT_FOUND`. PARENT не получает списки детей или управление. Пароли хранятся в Argon2id, сессии в виде хеша токена; временный пароль доступен только в ответе создания/сброса и не пишется в логи.
- Локальный preview не является продуктивной обработкой ПДн. Перед запуском с реальными данными необходимы отдельные организационные и правовые меры по 152-ФЗ, включая определение оснований обработки, доступов, сроков хранения и размещения инфраструктуры. Это не часть приёмки Stage 2.

## Воспроизведение

См. `PREVIEW.md` для запуска локально и `.github/workflows/ci.yml` для автоматической проверки. При изменении API или пользовательского пути обновлять контракт и этот сценарий вместе.
