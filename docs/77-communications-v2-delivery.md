# Communications v2 delivery

Issue #175 implementation is based on approved `main` `76399b653a4585a9ae5327170f0d8bfc5892ac09` and adds the single Alembic revision `0017_communications_v2.py` after `0016`.

## Covered behavior

- V2 group channels support `all` and internal `teachers` audiences. DIRECTOR/ADMIN can enter only group channels; PARENT sees only an eligible child's `all` channel.
- V2 direct threads are keyed by organization, active group, child, guardian, and assigned Teacher Employee. Teacher options expose only employee ID, display name and active group context. Eligibility is rechecked on each read and write.
- Grandfathered direct threads with `teacher_employee_id IS NULL` remain in the legacy API and data. V2 lists exclude them, and V2 access rejects them.
- Message creation requires a client UUID. A retry by the same sender in the same thread returns the first message; reusing the key in another thread returns `409 IDEMPOTENCY_KEY_REUSED`. Audit details contain context and identifiers, never body text.
- `CommunicationReadState` is private to its user and thread. The cursor can only reference a message in that same tenant/thread and moves forward by `(created_at, id)`. Thread lists calculate unread messages from other users after the cursor; they do not expose read receipts.
- One unread communication notification per recipient/thread and one unread announcement notification per recipient/announcement are enforced with PostgreSQL partial unique indexes and conflict-safe inserts.
- Announcements support `all`, `parents`, and `staff` audiences for organization or group targeting. Group fanout is limited to eligible Parents and active assigned Teachers; management visibility in the registry does not add management accounts to a Group audience. Organization audiences use eligible active Parent accounts and active Employee-linked TEACHER/ADMIN accounts. A Teacher can preview and publish only to an assigned active Group. The count-only preview and publish share the audience resolver, return total/parent/staff counts without recipient identities, and publication rechecks scope. The management and Teacher forms require review of the count and explicit audience confirmation before publish. Published target, group and audience are immutable; content edits do not issue another publish notification. Parent read state is self-only.
- Parent announcement list state stores navigation metadata without the announcement body. Opening performs a fresh authorized V2 detail GET; only a current successful detail response is rendered and then marked read. A denied detail/read clears the open content, and late responses cannot replace a newer selection.
- The existing legacy communications and announcement endpoints remain available. V2 does not add attachments, media, reactions, editing/deletion/forwarding of messages, or read receipts.
- Downgrade to `0016` is supported on an empty V2 data set. The migration refuses rollback after V2 direct threads, client-key messages, read states, non-`all` announcements, or publish notifications exist because removing them would widen access or erase user state.

## Verification coverage

`backend/tests/test_communications_v2.py` exercises PostgreSQL-backed direct eligibility, retries and cross-thread collisions, unread count/cursor monotonicity, relation/assignment revocation, tenant-safe read rejection, legacy `parents` Group denial on Parent V2 GET/POST/read with legacy data/API retained, all six organization/group announcement audience previews, assigned-Teacher scope, Group notification fanout, revoked-parent detail/read denial, private read state, and no notification resend on content edits. Existing Stage 6 communications and announcement tests remain in place.

The parent Playwright regression now uses synthetic children in different Groups, two assigned Teacher direct threads, and each child's `audience=all` Group channel. It verifies selected-Child filtering, delayed old-thread responses during A→B switching, retry draft/client-key retention after a failed send, that listing announcements does not mark them read, fresh detail authorization before content display, fail-closed behavior after a revoked detail request, and suppression of a late detail response after selecting another announcement. The Teacher cabinet regression verifies the direct title uses the current representative name, Child context, and factual `ChildGuardian.relation_type` supplied by the existing assigned-Group endpoint; its announcement form exercises count preview, explicit audience confirmation, then publish. The management announcement form has the same preview/confirmation gate. Both chat cabinets discard late message responses and hide messages whose active read/access check fails; backend tests cover eligibility revocation and role/tenant boundaries.

The targeted parent/Teacher cabinet Playwright flows assert no horizontal overflow at 320 px and 390 px and exercise delayed A→B response ordering in both cabinets. Parent browser coverage also revokes an open direct conversation and verifies private messages disappear while the unsent draft remains. PostgreSQL integration tests cover server-side eligibility revocation. Required CI browser checks remain the acceptance gate for the submitted changes.

The compatibility canary runs the Communications v2 and existing Stage 6/announcement integration tests against its PostgreSQL service. Its backup/recovery job checks that both source and recovered databases run on PostgreSQL 18 and invokes the disposable synthetic backup/restore verifier using PostgreSQL 18 client tools.

The local Work environment has no PostgreSQL service, so database integration and migration round-trip checks must be completed by CI. The feature's technical coverage does not establish production legal approval or authorize use of real personal data; production 152-FZ readiness remains subject to specialist review, deployment/data-location/subprocessor decisions, retention and destruction policy, and operational backup/access controls.
