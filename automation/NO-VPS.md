# Smart Garden — бесплатный облачный контроль разработки без VPS

**Состояние:** кандидат к интеграции в PR #205; **пока PR не смержен в `main`,
расписание не активно на основной ветке**. Этот режим не пишет код, не создаёт
PR, не объединяет их, не запускает Codex и не отправляет сообщения в Telegram.

## Что работает без владельца и банковской карты

После отдельного решения о merge в `main` GitHub Actions запускает
`.github/workflows/automation-observer.yml` раз в час (UTC, минутa 17),
по окончании workflow **CI**, при изменении состояния/меток GitHub Issues,
а также по кнопке **Run workflow**. Запуски по этим событиям работают **только после
merge workflow в default branch**; наблюдение не публикует комментарии и не
создаёт PR. В PR #205 тот же workflow запускается
на изменениях инфраструктуры и выполняет реальное read-only обращение к GitHub.

Используются GitHub-hosted runner и временный `GITHUB_TOKEN` с явными правами
`contents:read`, `issues:read`, `pull-requests:read`, `checks:read` — без PAT,
ChatGPT OAuth, API-ключа, VPS, Docker, n8n и денег за сторонние AI API.
Для текущего публичного репозитория стандартные GitHub-hosted runners доступны
бесплатно в рамках политики GitHub. Не включайте платные larger runners.

Observer читает:

1. Точный SHA текущей ветки `main`.
2. Открытые PR в `main` и восемь обязательных CI-checks по каждому HEAD SHA.
3. Только Issues с меткой `ai:ready`; проверяет автора, `BASE-SHA`,
   `WRITE-SET` и разрешение через тот же модуль `automation/worker/policy.py`.
4. Показывает компактную сводку в **Actions → запуск → Job summary**.
   Заголовки и содержимое Issues в отчёт не копируются.

## Жёсткие границы

- **Выполнение заданий отключено при любом состоянии очереди.** Метка
  `ai:ready` не запускает ИИ: даже при зелёном CI агент не стартует.
- При пропаже хоть одной обязательной проверки статус PR не бывает `passed`.
- Неполные ответы GitHub, слишком большие списки или недействительные SHA
  останавливают job вместо предположения об успешности.
- Открытый PR препятствует будущему серийному выпуску: очередь помечается
  `BLOCKED_OPEN_PR`. Это только индикация — никакой автоматики merge.
- Никаких production/152-ФЗ данных, автоматических развёртываний или
  изменений frozen contracts.
- Отправка Telegram пока **не интегрирована**: потребуются один раз бот,
  приватный chat ID и надёжное хранилище секрета. Не добавляйте токен в Issue,
  Git, ChatGPT или workflow artifacts. В прежнем n8n-шаблоне Telegram тоже
  отключён, пока не развёрнут отдельный сервер.
- ChatGPT Plus **не является API-ключом**: официальный Codex GitHub Action
  требует provider API key. Мы не копируем личный OAuth токен в CI и не
  обходим ограничения поддерживаемых регионов.

## Разделение проектных фаз

**Этап А — этот PR:** безопасное read-only наблюдение, инфраструктурные тесты,
отчёт по реальному GitHub. Никаких изменений frontend/backend/DB.

**Этап Б — отдельно и только после разрешения:** независимое ревью PR #205,
его merge в main и проверка первого scheduled/dispatch запуска. До merge
доказательство автоматического расписания получить нельзя: GitHub schedule
работает только для workflows из default branch. Расписание может задерживаться;
в публичных репозиториях GitHub может автоматически отключить его после 60 дней
отсутствия активности. Это не гарантированный realtime-сервис.

**Этап В — отдельный контракт:** подключение способа ИИ-исполнения,
доступного из поддерживаемой страны и с безопасной отдельной авторизацией,
с последующим пилотом только на синтетических данных. Текущая подписка Plus
сама по себе не делает официальный Codex Action бесплатным ИИ-исполнителем.

## Как принять инфраструктуру

Проверить в PR #205:

- `Automation policy tests` — все тесты и правила `WRITE-SET` зелёные;
- `Smart Garden automation observer (read only)` — реальный GitHub API
  доступен, в Job summary указаны номер открытых PR и состояние восьми checks;
- `CI` — все текущие обязательные product CI зелёные;
- статус PR по-прежнему Draft, никаких merge и новых продуктовых PR.

Если новая ветка `main` ушла вперёд, автор доставки синхронизирует инфраструктурный
PR с main в той же ветке без изменения продукта и перепроверяет CI.

## Отключение

До merge ничего включать не надо. После merge можно отключить workflow через
**Actions → Smart Garden automation observer → Disable workflow**. Это не
отключает существующий product CI. Ни в каком виде не требуется платный VPS.

Исторические инструкции Hetzner/Oracle и вариант n8n + Codex в README остаются
только **опциональными неразвёрнутыми** вариантами для будущего независимого
решения. В режиме без VPS они не используются.
