# Product Scope — что зафиксировано

**Кому читать:** обоим разработчикам перед добавлением новой функции.  
**Статус:** текущие границы продукта; запрещает самостоятельно добавлять функции будущих этапов.

## Концепция

«Умный сад» — SaaS-система управления частным детским садом.

Система должна постепенно объединить:
- администрацию;
- директора;
- воспитателей;
- родителей;
- посещаемость;
- коммуникацию;
- позже физическую точку входа через планшет.

---

# Роли

## DIRECTOR
Главный пользователь конкретного сада.

Может:
- контролировать сад;
- управлять детьми;
- группами;
- родителями;
- сотрудниками;
- посещаемостью;
- объявлениями;
- настройками;
- видеть audit.

Не является Super Admin всей платформы.

## ADMIN
Операционная роль.

Может выполнять ежедневную административную работу.

Не может:
- назначить DIRECTOR;
- расширить собственные права;
- видеть другие сады;
- менять критические настройки.

## PARENT
В MVP сначала существует учётная запись и связь с ребёнком.

Полноценный интерфейс позже.

Один PARENT может быть связан с несколькими детьми.

## TEACHER
Будет реализован позже.

Основной принцип:
видит только свои группы и минимально необходимые данные.

## SUPER_ADMIN
Будущий внутренний интерфейс команды «Умный сад».

Не входит в первый MVP.

---

# Аутентификация

Основной вариант:

```text
username + password
```

Email не обязателен.

Телефон не обязателен.

При создании аккаунта:
- система создаёт username;
- создаёт временный пароль;
- пользователь обязан сменить пароль после первого входа.

Восстановление доступа в раннем MVP:
через директора/администратора с reset временного пароля.

---

# Что не входит в первый MVP

- биометрия;
- Face ID;
- полноценный СКУД;
- платежи;
- AI;
- фотоотчёты;
- медицинский модуль;
- документы ребёнка;
- сложные интеграции;
- мессенджер.

---

# Планшет на входе

Решение зафиксировано концептуально, но вынесено в отдельный будущий этап.

На текущую разработку не влияет.

---

# Принцип продукта

Каждая новая функция должна:
1. решать конкретную проблему сада/родителя;
2. иметь понятную роль и права;
3. не создавать лишнюю ручную работу;
4. проходить проверку ПДн;
5. не ломать масштабирование SaaS;
6. по возможности быть одинаковой для всех садов, а не кастомной разработкой под каждого клиента.
